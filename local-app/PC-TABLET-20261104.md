# PC · 태블릿 공통 수업 조작

## 변경

- PC의 마우스·스페이스바와 태블릿의 터치를 공통 필수 조건으로 지정했다. 문장 생성, 최종 프롬프트, 게임 생성, 게임 수정에 적용한다.
- 원본 1번 질문은 날기 세기, 10번 질문은 다시 시작할 때의 안내를 선택한다. 기기나 입력 수단을 선택지로 고르지 않는다.
- 그림 선택지에서도 전화기/키보드를 제거하고 상승 높이와 재시작 안내를 표현했다.
- 예전 진행 기록은 나머지 8개 답과 이미 만든 게임을 유지한다. 바뀐 두 답과 기존 최종 문장은 `previousDeviceChoices`에 보관하고 해당 두 질문만 다시 묻는다.
- 게임의 Space 자동 반복을 차단했다. 재시작 뒤 현재 보이는 게임으로 키보드 초점을 돌린다.
- 생성 게임에 아래쪽 안내가 있을 때 그 높이를 제외하고 Canvas와 비율 고정 컨테이너를 함께 맞춘다. 게임 내부에 불필요한 스크롤이 생기지 않게 했다.
- 수업 화면의 안내와 최종 프롬프트에서 공통 조작을 확인할 수 있다.

## 확인한 내용

- `node --test device-support.test.mjs`: 4개 통과. 기존 답 보존, 중복 마이그레이션 방지, 공통 문장 중복 방지, 생성 API의 필수 조작 지침 전달.
- 실제 Chrome에서 새 질문 10개를 선택하고 AI 문장 생성·확정·최종 프롬프트까지 진행했다.
- 태블릿 가로 1024×768, 세로 768×1024에서 질문/답 선택지가 가로로 넘치지 않는다.
- 편집 미리보기의 다시 시작 후 DOM 초점이 게임 iframe으로 옮겨졌고, 실제 Space 입력으로 비행이 시작됐다.
- 실제 태블릿 하드웨어 터치는 검사하지 않았다. 브라우저 터치 모의 입력은 자동화 도구의 입력 제한으로 완료하지 못했고, 모의 설정을 해제했다. 기존 `pointerdown`의 마우스/터치 공용 처리와 `touch-action`은 코드로 확인했다.
- 임시 테스트 HTML을 공개 폴더에서 제거했다. 배포/원격 push는 하지 않았다.

## 생성 샘플 검사 기록

- 첫 신규 샘플은 빈 배경 이미지에서 `null.ok`를 읽어 실행이 중단됐다. 이미지가 없어도 기본 도형으로 실행하고 null을 검사하도록 생성 지침을 보강했다. 오류 원본은 로컬 evidence에 남겼다.
- 두 번째 독립 생성 요청은 완성 HTML 검사를 통과하지 못했다. 이 두 요청은 성공으로 집계하지 않는다.
- 실제 10단계 화면을 통한 최종 생성은 정상 완료됐다. 기본 그림이 표시되고 콘솔 오류가 없었다. Canvas 마우스 클릭으로 playing, 다시 시작 뒤 실제 Space 입력으로 playing 상태를 확인했다.
- 최종 게임의 태블릿 세로 화면에서 Canvas 원본 320×525 → 표시 286.525×470.1로 비율이 유지됐다. 문서 크기와 스크롤 크기는 모두 354×579로 넘침이 없었다.
- 기존 연습 게임도 다시 시작 후 Space로 비행했고 320:525 비율을 유지했다.
